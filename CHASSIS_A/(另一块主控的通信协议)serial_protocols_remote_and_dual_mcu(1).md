# 串口通信协议文档

本文档定义两套二进制串口协议：

1. 遥控器与主控通信协议
2. 上层主控与下层主控通信协议

两套协议均采用二进制帧格式，不追求文本可读性，优先考虑 STM32 等嵌入式平台解析简单、帧长较短、抗干扰能力明确。

## 1. 通用约定

### 1.1 字节序

所有多字节数据均使用小端格式。

例如：

```text
int16_t value = 0x1234
发送顺序为：34 12
```

### 1.2 数据类型

| 类型 | 长度 | 说明 |
|---|---:|---|
| `uint8` | 1 byte | 无符号 8 位整数 |
| `int16` | 2 bytes | 有符号 16 位整数 |
| `uint16` | 2 bytes | 无符号 16 位整数 |
| `uint32` | 4 bytes | 无符号 32 位整数 |

### 1.3 CRC 校验

协议使用 `CRC16-MODBUS`。

| 项目 | 值 |
|---|---|
| 多项式 | `0xA001` |
| 初始值 | `0xFFFF` |
| 输出格式 | 小端，低字节在前 |
| 覆盖范围 | 从 `VER` 到 `PAYLOAD`，不包含帧头和 CRC 本身 |

### 1.4 串口建议

| 通信链路 | 建议波特率 | 建议频率 |
|---|---:|---:|
| 遥控器 ↔ 主控 | `115200 bps` 或更高 | 遥控输入 `50~100 Hz`，主控状态 `10~20 Hz` |
| 上层主控 ↔ 下层主控 | `115200 bps` 可用，推荐 `460800 bps` | 控制帧 `50~100 Hz`，状态帧 `20~50 Hz` |

串口 8N1 格式下，每个字节约占 10 bit，因此 `115200 bps` 理论传输能力约为：

```text
115200 / 10 = 11520 byte/s
```

## 2. 协议一：遥控器 ↔ 主控

### 2.1 用途

该协议用于遥控器与主控之间通信。

遥控器向主控发送：

- 两个摇杆原始值
- 约 30 个按键状态
- 急停、数据有效等基础状态

主控向遥控器发送：

- 开机自检状态
- 各电机初始化成功状态
- 电机错误状态
- 当前错误码
- 动作执行情况

该协议不包含遥控配置帧，不包含遥控器电量，不包含链路质量，不包含遥控器开机时间。

### 2.2 通用帧格式

| 字段 | 长度 | 说明 |
|---|---:|---|
| `SOF` | 2 bytes | 帧头，固定 `A5 5A` |
| `VER` | 1 byte | 协议版本，当前 `0x01` |
| `MSG_ID` | 1 byte | 消息类型 |
| `SEQ` | 1 byte | 帧序号，`0~255` 循环 |
| `LEN` | 1 byte | Payload 长度 |
| `PAYLOAD` | N bytes | 数据区 |
| `CRC16` | 2 bytes | CRC16-MODBUS，小端 |

### 2.3 消息类型

| `MSG_ID` | 方向 | 名称 |
|---:|---|---|
| `0x10` | 遥控器 → 主控 | 遥控输入帧 |
| `0x80` | 主控 → 遥控器 | 主控状态帧 |

### 2.4 遥控器 → 主控：遥控输入帧

| 项目 | 值 |
|---|---|
| `MSG_ID` | `0x10` |
| Payload 长度 | `15 bytes` |
| 整帧长度 | `23 bytes` |
| 建议发送频率 | `50~100 Hz` |

#### Payload 格式

| 偏移 | 类型 | 名称 | 说明 |
|---:|---|---|---|
| 0 | `int16` | `joy_left` | 左摇杆原始值，范围 `-255~+255` |
| 2 | `int16` | `joy_right` | 右摇杆原始值，范围 `-255~+255` |
| 4 | `uint32` | `buttons` | 30 个按键状态位图 |
| 8 | `uint8` | `flags` | 遥控状态标志 |
| 9 | `uint8` | `reserved1` | 保留，发送端置 `0` |
| 10 | `uint8` | `reserved2` | 保留，发送端置 `0` |
| 11 | `int16` | `shoulder_left` | 左线形肩键，范围 `-64~+64` |
| 13 | `int16` | `shoulder_right` | 右线形肩键，范围 `-64~+64` |

#### buttons 位定义

| bit | 含义 |
|---:|---|
| 0 | `KEY1` |
| 1 | `KEY2` |
| 2 | `KEY3` |
| ... | ... |
| 29 | `KEY30` |
| 30 | 保留 |
| 31 | 保留 |

按键位定义：

```text
0 = 松开
1 = 按下
```

#### flags 位定义

| bit | 含义 |
|---:|---|
| 0 | 急停 |
| 1 | 摇杆数据有效 |
| 2 | 按键数据有效 |
| 3~7 | 保留 |

### 2.5 主控 → 遥控器：主控状态帧

| 项目 | 值 |
|---|---|
| `MSG_ID` | `0x80` |
| Payload 长度 | `20 bytes` |
| 整帧长度 | `28 bytes` |
| 建议发送频率 | `10~20 Hz` |

如果发生错误、急停、动作完成、动作失败等关键状态变化，主控可以立即额外发送一帧状态帧。

#### Payload 格式

| 偏移 | 类型 | 名称 | 说明 |
|---:|---|---|---|
| 0 | `uint8` | `system_state` | 主控整体状态 |
| 1 | `uint8` | `self_check` | 开机自检结果 |
| 2 | `uint8` | `action_id` | 当前动作编号 |
| 3 | `uint8` | `action_result` | 动作执行结果 |
| 4 | `uint32` | `motor_init_bitmap` | 电机初始化成功位图 |
| 8 | `uint32` | `motor_fault_bitmap` | 电机错误位图 |
| 12 | `uint16` | `error_code` | 当前主要错误码 |
| 14 | `uint16` | `status_flags` | 主控状态标志 |
| 16 | `uint16` | `extra` | 扩展状态，可选 |
| 18 | `uint16` | `reserved` | 保留，发送端置 `0` |

#### system_state 定义

| 值 | 含义 |
|---:|---|
| `0` | 未初始化 |
| `1` | 自检中 |
| `2` | 空闲 |
| `3` | 遥控运行中 |
| `4` | 自动动作中 |
| `5` | 急停 |
| `6` | 故障 |

#### self_check 定义

| 值 | 含义 |
|---:|---|
| `0` | 未完成 |
| `1` | 自检通过 |
| `2` | 自检失败 |

#### action_id 建议定义

| 值 | 含义 |
|---:|---|
| `0` | 无动作 |
| `1` | 正常遥控 |
| `2` | 取物配合 |
| `3` | 放置配合 |
| `4` | 对准目标 |
| `5` | 视觉辅助运动 |
| `6` | 回零/复位 |
| `7~255` | 项目自定义 |

| 值 | 含义 |
|---:|---|
| `0x10` | 手动抓取 |
| `0x11` | 手动放块 |
| `0x12` | 自动开始位置对准 |
| `0x13` | 自动抓取 |
| `0x14` | 自动放块 |

| `2` | 动作完成 |
| `3` | 动作失败 |

| 值 | 含义 |
|---:|---|
| `0` | 无错误 |
| `1` | 遥控通信超时 |
| `2` | 电机初始化失败 |
| `3` | 电机运行错误 |
| `4` | 动作执行失败 |
| `5` | 急停触发 |
| `6` | 主控内部错误 |
| `7~65535` | 项目自定义 |

#### status_flags 位定义

| bit | 含义 |
|---:|---|
| 0 | 主控在线 |
| 1 | 自检完成 |
| 2 | 自检成功 |
| 3 | 所有电机初始化成功 |
| 4 | 存在电机错误 |
| 5 | 正在执行动作 |

| 7 | 动作失败 |
| 8 | 急停状态 |
| 9 | 遥控失联 |
| 10~15 | 保留 |

### 2.6 遥控协议异常处理建议

主控接收遥控输入帧时：

- 帧头错误：继续寻找下一个 `A5 5A`。
- `LEN` 不等于 `15`：丢弃该帧。
- CRC 错误：丢弃该帧。
- `joy_left` 或 `joy_right` 超出 `-255~+255`：丢弃该帧。
- `shoulder_left` 或 `shoulder_right` 超出 `-64~+64`：丢弃该帧。
- `flags.bit0 = 1`：立即急停。
- 超过 `100 ms` 没有收到有效遥控输入帧：遥控输入清零。
- 超过 `300 ms` 没有收到有效遥控输入帧：进入遥控失联状态。

遥控器接收主控状态帧时：

- CRC 错误：丢弃该帧。
- `system_state = 5`：显示急停状态。
- `system_state = 6` 或 `error_code != 0`：显示错误状态。
- `status_flags.bit6 = 1`：显示动作完成。
- `status_flags.bit7 = 1`：显示动作失败。

### 2.7 遥控协议带宽估算

遥控输入帧：

```text
23 byte * 50 Hz = 1150 byte/s
```

主控状态帧：

```text
28 byte * 20 Hz = 560 byte/s
```

总计：

```text
1150 + 560 = 1710 byte/s
```

在 `115200 bps` 串口下约占：

```text
1710 / 11520 = 14.8%
```

因此该协议在 `115200 bps` 下也比较宽松。

## 3. 协议二：上层主控 ↔ 下层主控

### 3.1 用途

该协议用于上层主控与下层主控通信。

上层主控向下层主控发送：

- 控制模式
- 动作编号
- 控制标志
- 遥控两个摇杆与两个线形肩键的原始值
- 动作参数

下层主控向上层主控发送：

- 下层主控状态
- 当前动作编号
- 动作执行结果
- 故障码
- 状态标志

该协议中，上层主控不向下层发送按键位图。按键含义由上层主控解析后，转换为具体 `action_id` 和控制标志发送给下层主控。

该协议中，上层主控不接收下层主控的 IMU 和 DT35 数据。下层主控只回传动作完成、动作失败、故障等状态。

### 3.2 通用帧格式

| 字段 | 长度 | 说明 |
|---|---:|---|
| `SOF` | 2 bytes | 帧头，固定 `55 AA` |
| `VER` | 1 byte | 协议版本，当前 `0x01` |
| `MSG_ID` | 1 byte | 消息类型 |
| `SEQ` | 1 byte | 帧序号，`0~255` 循环 |
| `LEN` | 1 byte | Payload 长度 |
| `PAYLOAD` | N bytes | 数据区 |
| `CRC16` | 2 bytes | CRC16-MODBUS，小端 |

### 3.3 消息类型

| `MSG_ID` | 方向 | 名称 |
|---:|---|---|
| `0x20` | 上层主控 → 下层主控 | 控制指令帧 |
| `0x21` | 下层主控 → 上层主控 | 动作状态帧 |

### 3.4 上层主控 → 下层主控：控制指令帧

| 项目 | 值 |
|---|---|
| `MSG_ID` | `0x20` |
| Payload 长度 | `12 bytes` |
| 整帧长度 | `20 bytes` |
| 建议发送频率 | `50~100 Hz` |

#### Payload 格式

| 偏移 | 类型 | 名称 | 说明 |
|---:|---|---|---|
| 0 | `uint8` | `control_mode` | 控制模式 |
| 1 | `uint8` | `action_id` | 动作编号 |
| 2 | `uint8` | `flags` | 控制标志 |
| 3 | `uint8` | `reserved` | 保留，发送端置 `0` |
| 4 | `int16` | `rc_joy_left` | 遥控左摇杆原始值，范围 `-255~+255` |
| 6 | `int16` | `rc_joy_right` | 遥控右摇杆原始值，范围 `-255~+255` |
| 8 | `int16` | `shoulder_left` | 左线形肩键原始值，范围 `-64~+64` |
| 10 | `int16` | `shoulder_right` | 右线形肩键原始值，范围 `-64~+64` |

#### control_mode 定义

| 值 | 含义 |
|---:|---|
| `0` | 禁能，底盘停止 |
| `1` | 遥控原始控制 |
| `2` | 自动动作配合 |
| `3` | 保持当前位置或姿态 |
| `4` | 急停 |
| `5~255` | 保留 |

#### action_id 建议定义

| 值 | 含义 |
|---:|---|
| `0` | 无动作 |
| `1` | 正常遥控 |
| `2` | 取物配合 |
| `3` | 放置配合 |
| `4` | 对准目标 |
| `5` | 视觉辅助运动 |
| `6` | 回零或复位 |
| `7~255` | 项目自定义 |

#### flags 位定义

| bit | 含义 |
|---:|---|
| 0 | 底盘使能 |
| 1 | 急停 |
| 2 | 摇杆数据有效 |
| 3 | 动作指令有效 |
| 4~7 | 保留 |

### 3.6 推荐发送内容

#### 遥控驾驶

```text
control_mode = 1
action_id = 1
flags.bit0 = 1
flags.bit2 = 1
rc_joy_left = 遥控左摇杆原始值
rc_joy_right = 遥控右摇杆原始值
shoulder_left = 遥控左线形肩键原始值
shoulder_right = 遥控右线形肩键原始值
```

#### 自动动作

```text
control_mode = 2
action_id = 对应动作编号
flags.bit0 = 1
flags.bit3 = 1
rc_joy_left = 0
rc_joy_right = 0
```

#### 急停

```text
control_mode = 4
action_id = 0
flags.bit1 = 1
rc_joy_left = 0
rc_joy_right = 0
```

### 3.7 下层主控异常处理建议

下层主控接收控制指令帧时：

- 帧头错误：继续寻找下一个 `55 AA`。
- `LEN` 不等于 `12`：丢弃该帧。
- CRC 错误：丢弃该帧。
- `rc_joy_left` 或 `rc_joy_right` 超出 `-255~+255`：丢弃该帧。
- `shoulder_left` 或 `shoulder_right` 超出 `-64~+64`：丢弃该帧。
- `flags.bit1 = 1` 或 `control_mode = 4`：立即急停。
- `control_mode = 0`：底盘禁能，速度目标清零。
- 超过 `100 ms` 没有收到有效控制指令帧：速度目标清零。
- 超过 `300 ms` 没有收到有效控制指令帧：进入上层通信超时状态。

上层主控接收动作状态帧时：

- CRC 错误：丢弃该帧。
- `action_result = 2` 或 `status_flags.bit2 = 1`：认为动作完成。
- `action_result = 3` 或 `status_flags.bit3 = 1`：认为动作失败。
- `chassis_state = 5` 或 `status_flags.bit6 = 1`：认为下层急停。
- `fault_code != 0`：记录下层故障。

### 3.8 双主控协议带宽估算

上层到下层控制指令帧：

```text
20 byte * 50 Hz = 1000 byte/s
```

下层到上层动作状态帧：

```text
16 byte * 50 Hz = 800 byte/s
```

总计：

```text
1000 + 800 = 1800 byte/s
```

在 `115200 bps` 串口下约占：

```text
1800 / 11520 = 15.6%
```

因此该协议在 `115200 bps` 下可用。如果后续增加大量传感器数据或日志数据，建议提高到 `460800 bps` 或更高。

## 4. 实现建议

### 4.1 接收状态机

建议串口接收使用状态机，不建议直接假设一次中断能收到完整一帧。

典型状态：

```text
WAIT_SOF_1
WAIT_SOF_2
READ_VER
READ_MSG_ID
READ_SEQ
READ_LEN
READ_PAYLOAD
READ_CRC_L
READ_CRC_H
CHECK_FRAME
```

## 5. MainController_Work implementation profile

- UART4 (PA0 TX, PA1 RX) is the remote link at 115200 8N1. It accepts `0x10`,
  clears joystick targets after 100 ms, reports offline after 300 ms, and sends
  `0x80` every 100 ms plus an immediate status frame after status changes.
- The remote link uses `VER=0x01`; its `0x10` payload appends `int16`
  `shoulder_left` and `shoulder_right` at offsets 11 and 13, each limited to
  `-64~+64`.
- The dual-MCU link uses `VER=0x01`. Its control message `0x20` uses a 12-byte
  payload with `int16` `shoulder_left` and `shoulder_right` at offsets 8 and 10. Each is
  limited to `-64~+64`.
- UART8 (PE1 TX, PE0 RX) is the upper-controller link at 115200 8N1. It sends
  the `0x20` control frame every 20 ms and receives `0x21` lower-controller
  status frames.
- Both links use DMA RX/TX and UART idle events. RX callbacks only copy one
  DMA block to their own queue and restart DMA; parsing and TX queue handling
  run in their dedicated RTOS tasks.

### 4.2 SEQ 使用建议

`SEQ` 用于判断丢帧和重复帧。

- 发送端每发送一帧，`SEQ` 加 1。
- 接收端发现 `SEQ` 不连续时，可以记录通信丢帧。
- 控制类通信不建议依赖 ACK 重发，应该依靠周期发送和超时保护。

### 4.3 控制安全建议

所有运动相关链路都应该设置超时保护。

推荐原则：

- 通信数据非法时，不更新控制目标。
- 通信短暂丢帧时，保持上一帧或逐渐降速。
- 通信超时超过 `100 ms` 时，速度目标清零。
- 通信超时超过 `300 ms` 时，进入失联或故障状态。
- 任意急停标志出现时，立即停止运动。
