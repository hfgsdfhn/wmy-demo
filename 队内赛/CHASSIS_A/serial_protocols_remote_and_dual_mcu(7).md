# 遥控与双主控串口协议入口

状态：兼容入口，不单独定义线上字节格式  
当前协议版本：2026-08-18 RC_STATE profile

## 1. 唯一当前规范

遥控器、手机、LoRa、分电板及机器人主控接收口统一执行：

[`电源板_主控_串口协议交接.md`](./电源板_主控_串口协议交接.md)

字段偏移、帧长、按键位图、ADC 映射、肩键状态、CRC、超时语义和电源语义均以该文件为准。本文件不得复制或重新定义这些字段，避免两份协议再次漂移。

当前冻结值：

```text
SOF       A5 5A
VER       01
RC_STATE  MSG=10 LEN=18 FRAME=27 SEQ=uint16 little-endian
RC_STATUS MSG=80 LEN=14 FRAME=23 SEQ=uint16 little-endian
CRC       CRC16-Modbus, cover VER through payload
```

肩键每侧只有四个业务状态：

| 状态值 | 含义 |
| ---: | --- |
| 0 | 未操作 |
| 1 | 拨动方向 1 |
| 2 | 按下 |
| 3 | 拨动方向 2 |

线上沿用 `keys` 中每侧三个 one-hot bit，具体 bit 和 ADC 阈值只在唯一当前规范中定义。接收端必须将它们解码为一个四态值，不得当作六个独立按键或 `-64..64` 线性量。

## 2. 当前已实现链路

```text
手机 <-> 遥控器 USART2（ASCII 命令和诊断）
遥控器 <-> LoRa <-> 分电板（RC_STATE / RC_STATUS）
分电板  -> 机器人主控 1 USART1（合法 RC_STATE 原帧）
分电板  -> 机器人主控 2 USART2（合法 RC_STATE 原帧）
```

两个机器人主控接收口拿到完全相同的 `RC_STATE` 原帧，不存在第二套遥控输入格式。

## 3. 双主控协议状态

旧草案曾定义 `SOF=55 AA`、`MSG_ID=0x20/0x21` 的“上层主控与下层主控”协议，但当前仓库没有对应生产实现，也没有完成接口冻结。因此：

- `0x20/0x21` 不属于当前协议。
- 不得基于旧草案开发或联调。
- 后续确需增加主控间双向控制/状态协议时，应新建独立规范和双方实现，并分配独立版本、消息 ID、测试向量及超时语义。
- 新协议不得修改或复用当前 `RC_STATE/RC_STATUS` 的既有字段含义。

## 4. 已废弃内容

以下内容只存在于早期草案，已从本文件移除：

| 旧定义 | 当前定义 |
| --- | --- |
| `SEQ` 为 `uint8` | `SEQ` 为 `uint16` 小端 |
| `RC_STATE LEN=19` | `RC_STATE LEN=18`，整帧 27 字节 |
| 约 30 个模糊按键位 | 14 个普通按键、左右肩键四态、6 个拨杆 |
| 肩键为 `-64..64` 线性值 | 肩键为每侧四态 |
| 主控状态使用旧自检/动作 payload | 当前回包为 `RC_STATUS LEN=14` |
| `0x20/0x21` 双主控帧可直接实施 | 尚未实现、尚未冻结 |
